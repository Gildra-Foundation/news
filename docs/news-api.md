# API готовых новостей GildraNews

API отдаёт проверенные развёрнутые статьи для backend сайта. Запрос читателя не запускает
AI и не создаёт публикаций. Telegram-пост и статья — разные тексты из одного исходника.

## Настройка

Основной провайдер — официальный [Anthropic Messages API](https://platform.claude.com/docs/en/api/messages/create).
Модель по умолчанию — [`claude-sonnet-5-5`](https://platform.claude.com/docs/en/models/overview).
Ключ читается из `ANTHROPIC_API_KEY` либо приватного файла `ANTHROPIC_API_KEY_FILE`.
Прежний явно настроенный `AI_PROVIDER=app_server` сохраняется до изменения конфигурации.

В `.env`:

```dotenv
AI_PROVIDER=anthropic
ANTHROPIC_MODEL=claude-sonnet-5-5
ANTHROPIC_API_KEY_FILE=/app/data/anthropic_api_key
WEBSITE_NEWS_ENABLED=true
NEWS_API_TOKEN_FILE=/app/data/news_api_token
```

При запуске в контейнере файлы соответствуют `data/anthropic_api_key` и
`data/news_api_token` на сервере. Храните их с правами `0600`, не в Git.
В backend сайта хранится тот же `NEWS_API_TOKEN`; браузер обращается к backend,
а не получает этот токен. По умолчанию порт API открыт только на loopback сервера.

Создание нового токена без вывода его в терминал (существующий файл не перезаписывается):

```bash
python - <<'PY'
import os
import secrets

descriptor = os.open("data/news_api_token", os.O_WRONLY | os.O_CREAT | os.O_EXCL, 0o600)
with os.fdopen(descriptor, "w") as token_file:
    token_file.write(secrets.token_urlsafe(32))
PY
```

Запуск после согласованного обновления сервиса:

```bash
docker compose --profile website up -d --build
```

Нужно обновить оба сервиса вместе: API и бот используют одну базу и миграцию схемы 4.
API можно запустить и отдельно командой `python -m gildranews.news_api` из каталога проекта
с теми же переменными окружения. По умолчанию адрес — `127.0.0.1:8088`.

## Получение статей

Все `/v1/*` запросы требуют `Authorization: Bearer <NEWS_API_TOKEN>`.

`GET /v1/news?after_id=0&limit=20` возвращает:

```json
{
  "items": [
    {
      "id": 1,
      "published_at": "2026-10-11T10:30:00Z",
      "title": "На PTR снизили урон в рейде",
      "summary": "Изменение проходит тестирование.",
      "body": "Развёрнутый текст статьи с абзацами.",
      "key_points": ["Урон снизили на 15%.", "Изменение ещё не действует на обычных серверах."],
      "sources": [{"url": "https://example.com/news", "published_at": "2026-10-11T09:00:00+00:00"}],
      "game_branch": "retail",
      "version": "12.2.5",
      "information_status": "testing",
      "effective_date": "",
      "story_key": "opaque-story-hash",
      "revision_key": "opaque-revision-hash"
    }
  ],
  "next_cursor": 1,
  "has_more": false
}
```

Пример показывает структуру, а не реальную новость. `body` — обычный текст с `\n\n`
между абзацами. Сайт экранирует текст при отображении и формирует разметку самостоятельно.
`sources` содержит доступный первоисточник материала; наличие одной ссылки не означает
независимую проверку несколькими источниками. Неизвестные строки пусты, ветка и статус
могут иметь значение `unknown`, если источник Telegram не содержал этих метаданных.

`limit`: от 1 до 100. `after_id`: целое число от 0. Статьи упорядочены по возрастанию ID.
Сохраняйте `next_cursor` только после успешной обработки полученных статей. Даже при
`has_more=false` следующий периодический запрос использует сохранённый курсор.
ID назначается при готовности статьи, поэтому поздняя генерация не теряется за курсором.
`published_at` — момент готовности статьи в UTC; дата исходника хранится в `sources`.
Один сюжет может получить несколько существенных обновлений; `story_key` связывает их,
а `revision_key` идентифицирует набор новых фактов. Пустые ключи не следует группировать.

`GET /v1/news/{id}` возвращает тот же объект статьи без обёртки списка.
Ошибки имеют формат `{"error":{"code":"not_found","message":"Article not found"}}`:
400 — неверные параметры, 401 — нет токена, 404 — статья не найдена, 405 — метод запрещён.
API не предоставляет операции генерации, редактирования или публикации через HTTP.

## Генерация и проверки

При `WEBSITE_NEWS_ENABLED=true` только успешно опубликованная новость создаёт задание
в той же транзакции, что и запись публикации. Исходный текст сохраняется отдельно от
короткого поста, максимум 24 000 символов. Текст из RSS зависит от наполнения самой ленты;
если источник краткий, статья также остаётся краткой и не дополняется из памяти модели.

Worker делает черновик из исходника, сверяет точные цитаты и числа, при настроенном
`EDITOR_URL` вызывает совместимый `/v2/edit`, затем проводит отдельную проверку готового
текста по исходнику. Неподтверждённые утверждения, потеря существенных фактов или
неверный статус события блокируют выдачу. Проверка моделью снижает риск ошибок,
но не заменяет независимое исследование первичных источников.

Все публичные поля проходят проверку непереведённых названий и редакторских клише.
Названия локаций, предметов и боссов пишутся по-русски; оригинальный язык сохраняется
только в служебных цитатах и разрешённых названиях игры, дополнений и сокращениях.
Повтор лида в начале текста исправляется. Автоматически обнаруженные нарушения получают
один проход исправления; замечания итоговой проверки — ещё один, после которого статья
снова проверяется целиком. Числа и цитаты сверяются после каждого исправления.
Неудачная правка не считается готовой статьёй.

Правила сохранности фактов и происхождения заимствованы из обновлённого
[ResearchTeam](https://github.com/Manacost-Labs/ManacostTeam/tree/main/research).
Контракт редактора проверен по
[EditorTeam](https://github.com/Manacost-Labs/ManacostTeam/blob/main/editor/MIGRATION.md).
ResearchTeam — исследовательский workflow; этот API не выдаёт генерацию из RSS за
полноценный запуск deep-research или поиск независимых подтверждений.

При ошибке задание повторяется через пять минут, максимум три попытки. После исчерпания
попыток оно остаётся в `website_jobs` со статусом `failed`; статья недоступна читателям.
Внутренние evidence и исходники не выдаются через API. Прерванное задание восстанавливается
после истечения аренды; устаревший worker не может опубликовать результат повторно.
